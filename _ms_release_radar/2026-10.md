# Microsoft Security Release Radar - October 2026

## 🛡️ Microsoft Defender Cloud

| Indicator | Feature | Type | Description |
|---|---|---|---|
| 🔵 | New Defender server security experience | New/Updated | Public preview (announced October 6, 2026); brings cloud and endpoint data together in the Defender portal with unified server inventory, attack-graph investigation, Go hunt, and RBAC-managed access. |
| 🟢 | KSPM misconfiguration recommendations moving to controller-level scope | GA | GA (October 5, 2026); Kubernetes misconfiguration recommendations now scope to the container deployment or top-level controller (Deployment/StatefulSet) instead of individual running container instances, which can change affected recommendations and Secure Score impact. |
| 🟢 | On-demand malware scanning now supports scanning specific blobs, files, containers, and file shares | GA | GA (October 5, 2026); Defender for Storage on-demand scanning can target a single blob or file, a specific container or file share, or all objects matching a path prefix instead of the entire storage account. |

## 🐙 GitHub Security

| Indicator | Feature | Type | Description |
|---|---|---|---|
| 🔵 | Purpose-built model for leaked secret detection | New/Updated | New fine-tuned model brings context-aware secret detection to secret scanning alerts, push protection, and GitHub Copilot security reviews; AI-detected secrets in push protection is in private preview and AI-based scanning via the Copilot /security-review command is coming soon in private preview. |
| 🟢 | Local sandboxing for GitHub Copilot now generally available | GA | GA in GitHub Copilot CLI, the Copilot app, and VS Code Agent Host sessions; MXC-backed local sandboxes restrict filesystem, network, and credential access based on developer or organization policy and can be enforced with enterprise-managed settings at no additional cost. |
| 🔵 | Code scanning AI Scan enablement status in security overview | New/Updated | Organization and enterprise administrators can now see AI Scan for pull requests enablement in the security overview coverage view, with repository counts, filters, and CSV export columns. |
| 🔵 | Rate limits for private vulnerability reports | New/Updated | Daily per-user rate limits now apply to new private vulnerability reports, with repository-level custom overall limits and trusted-reporter allow lists, to reduce bulk and automated low-quality submissions. |
| 🔵 | Structured forms for private vulnerability reports | New/Updated | Private vulnerability reports can now use a customizable structured form with required fields (summary, details, proof of concept, impact), an optional required CWE, and an AI-assistance disclosure checkbox. |
| 🔵 | Scheduled code scanning skips inactive repositories | New/Updated | Weekly scheduled scans for code scanning default setup and GitHub Code Quality now start only after a push or pull request triggers an analysis, so dormant repositories no longer receive unexpected scans; the initial validation scan still runs. |
| 🔵 | Code coverage uploads no longer fail CI for new branches | New/Updated | The upload-code-coverage action no longer fails CI on pushes to a branch without an open pull request; it skips the upload and explains why in the Actions notice and step summary. Previously the coverage API required a pull request number. |
| 🔵 | Secret scanning adds detectors for Lovable, Supabase, and more | New/Updated | Secret scanning now detects lovable_api_key, logfire_token, pydantic_ai_gateway_api_key, and Supabase OAuth access and scoped personal access tokens; Lovable Labs joined the secret scanning partner program. |
| ⚫ | Unvalidated npm trusted publishing configurations now expire | Deprecation | Unvalidated npm trusted publishing configurations expire 48 hours after creation and can no longer authorize publishing unless validated by a first successful publish; npm also now rejects trusted publishing tokens from GitHub Actions issue_comment events. |
| 🔵 | npm staged publishing now supports creating new packages | New/Updated | npm stage publish can now create new public scoped/unscoped and private scoped packages using a local session or granular access token, with the first version entering the staged queue for maintainer promotion. |
| 🔵 | New fields for SecurityAdvisory GraphQL API | New/Updated | The SecurityAdvisory object gains cveId, sourceCodeLocation, githubReviewedAt, nvdPublishedAt, and repositoryAdvisoryUrl, plus severities and isWithdrawn query filters; changes are additive and read-only. |
| 🔵 | Confidential comments on repository security advisories | New/Updated | Maintainers can post confidential comments visible only to people with write access; access follows current repository permissions and views of confidential comments are recorded in the audit log. |
| 🟡 | Repository security advisory comments API in public preview | Preview | Public preview of REST API endpoints to list, get, add, and edit comments on repository security advisories, with comment counts returned on advisory responses; confidential comments aren't returned by these endpoints. |

## Security Architect Observations

- Defender for Cloud's new server security experience and the KSPM controller-scope change both push toward consolidated cloud-plus-endpoint governance; expect inventory, recommendation counts, and Secure Score baselines to shift, so re-validate scorecards before reporting to leadership.
- On-demand malware scanning with targeted scopes reduces storage-account-wide scanning blast radius and cost, enabling more surgical, event-driven inspection policies in Defender for Storage.
- Defender for Cloud Apps auto-enabling the SaaS accounts integration widens identity-inventory visibility by default, which improves SaaS discovery but should be reconciled against existing Entra ID and Defender for Identity coverage to avoid duplicate or conflicting ownership.
- The GitHub Copilot local sandboxing GA (MXC, cross-platform) is the notable defense-in-depth control for AI agent workflows; enterprise-managed settings should be wired into governance so developers cannot weaken required policies.
- Intune's Windows 11 26H2 baseline is a versioned security control set that doesn't auto-update existing profiles — treat baseline versioning as change management, and review customized settings before migration to avoid silent control drift.
- GitHub's structured vulnerability report forms and advisory comment/RBAC changes tighten the supply-chain reporting workflow; align internal PSIRT and disclosure processes and confirm API integrations still match enforced custom forms.

## Security Operations Observations

- Enable confidential comments and structured forms on private vulnerability reports to reduce low-quality/AI-generated noise and keep sensitive triage discussion out of reporter visibility; note confidential comments are excluded from the new REST API.
- Daily rate limits on private vulnerability reports and trusted-reporter allow lists should be tuned per repository to avoid blocking legitimate researchers while suppressing bulk submissions.
- Weekly scheduled code scanning now skips dormant repositories, so SOC teams relying on scheduled findings should add push/PR-driven scans or explicit monitoring for repos with no recent activity.
- The local sandboxing GA changes expectations for agentic tool execution monitoring; update detection content to distinguish sandboxed versus unsandboxed Copilot activity and to watch enterprise policy enforcement.
- Secret scanning's new providers (Lovable, Pydantic/Logfire, Supabase) and the purpose-built AI secret model will change secret-alert volume and false-positive profiles; retune alert routing and push-protection workflows accordingly.
- New SecurityAdvisory GraphQL fields and filters enable severity-based triage feeds and withdrawn-advisory audits, allowing enrichment pipelines to reduce round trips and stale-advisory noise.
