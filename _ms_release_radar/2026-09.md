## Security Architect Observations

- **Deprecation debt is clustering around runtime and OS lifecycles.** Azure Functions .NET 8/9, PowerShell 7.4, Node.js 22, Functions on ACA V1, AKS Windows Server 2022, Flatcar, and Azure Linux with OS Guard all reach end of support within the planning horizon. A single platform-lifecycle register covering compute runtimes and node images would prevent these from arriving as separate emergencies.
- **Sovereign cloud parity is improving but uneven.** Defender for SQL Servers enhanced agent, Defender for Cosmos DB, Cloud PKI, and Remote Help expanded into Azure Government or GCC High, while DoD remains excluded for Cloud PKI and Remote Help. Architecture standards for regulated clouds should record these gaps explicitly.
- **Identity defaults are shifting toward agent-aware, signal-driven control.** Universal CAE now consumes user-risk and device-revocation signals, the Identity Security dashboard adds coverage scoring, and Defender for Identity enables sensor v3.x and Windows auditing by default. Default-on telemetry changes reduce blind spots but bypass change control, so opt-out windows must be governed.
- **Network-layer data security is consolidating.** Purview DLP via Global Secure Access and Microsoft-managed TLS inspection certificates move enforcement from endpoint agents to the network path, which changes where inspection, breakage, and certificate trust risks sit in the architecture.
- **Automation and agent execution need explicit trust boundaries.** AKS Sandboxes, WSL container protection, MDE AI agent runtime protection, and Copilot agent tool permissions all extend execution of untrusted or AI-generated content. Architectures should define isolation tier, egress control, and audit trail per execution surface rather than per product.
- **SIEM and lake architecture is converging on the Defender portal.** Integrated Sentinel onboarding, lake-tier retention via Table management, and Fabric mirroring remove the separate data lake onboarding step but change retention, cost, and data-residency assumptions that compliance owners previously documented.

## Security Operations Observations

- **High-priority detection coverage changes arrive as previews.** Linux memory scanning, Linux desktop support, WSL container visibility, and sensor v3.x coverage for AD CS/AD FS/Entra Connect all alter what the SOC can see. Update detection coverage matrices and tuning baselines before enabling, and expect a temporary rise in low-fidelity memory and container alerts.
- **Default-on Defender for Identity auditing will change event volume.** Automatic sensor v3.x activation and Windows event auditing can materially increase domain controller telemetry and identity alerts in tenants that had these disabled; confirm ingestion capacity and alert routing during the 30-day notice window.
- **AKS upgrade work has direct detection impact.** LocalDNS auto-enable, namespace-scoped Prometheus secrets, reserved label rejection, and stricter LoadBalancer validation can silently break monitoring or admission pipelines; SOC should verify Prometheus scrape health and Defender for Containers coverage after each cluster upgrade.
- **Scanner noise needs a documented exception workflow.** The AKS OpenSSL end-of-life bulletin and the MDVM inaccuracy fixes (including CVE-2024-47611 false positives) show that distribution-aware matching and time-bound exceptions are required to keep vulnerability queues actionable.
- **Insider and user-reporting signals broaden.** Teams group-call reporting, separated Teams versus email reporting destinations, and Purview network DLP events add triage paths that must be mapped to existing incident queues to avoid orphaned reports.
- **Deprecated grouped recommendation splits the vulnerability workflow.** The retirement of "Machines should have a vulnerability assessment solution" on December 14, 2026 means dashboards, Workbooks, and automation keyed to that recommendation ID must move to the individual recommendations before the cutoff.
