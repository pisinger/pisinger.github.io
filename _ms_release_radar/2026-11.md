| 🔴 | AKS-2026-0008 advisory for CVE-2026-111497 (Brotli decoder) | Security | High | Vulnerability in the Brotli decoder can expose memory, crash, or allow remote code execution when decompressing malicious data. Rebuild affected container images and customer-managed proxies; patching the node OS does not fix packages inside containers. Azure Linux 3.0 node image `202610.23.0` includes the fix, Ubuntu VHD `202610.30.0` is planned, and the Ubuntu `SecurityPatch` channel is rolling out with all-region availability expected by November 12, 2026. |
| 🔴 | AKS-2026-0007 advisory and mitigation guide for CVE-2026-99999 and CVE-2026-98432 | Security | High | Two Linux kernel IPv4 networking vulnerabilities affect AKS Linux nodes. CVE-2026-98432 is a use-after-free that can allow unauthenticated remote command execution as root on hosts with an MPTCP listener; CVE-2026-99999 allows a local attacker or untrusted guest VM to gain code execution on the host, cause a DoS crash, or disclose memory. Node image and `SecurityPatch` channel updates are required. |
| 🔴 | AKS-2026-0006 OpenSSL end-of-life scanner findings in AKS-managed add-on images | Security | Medium | Explains that OpenSSL 3.3 upstream EOL warnings reported against Azure Linux 3.0 add-on images (CoreDNS, metrics-server, CSI components) do not by themselves prove a missing security patch, because Microsoft backports fixes without changing the upstream version (e.g. CVE-2026-45447, CVE-2026-54874). Verify the full package revision from SBOM/RPM metadata and handle verified EOL-only findings through time-bound exceptions rather than modifying managed images. |

## Security Architect Observations

- The AKS bulletins reinforce a layered patching model: node OS remediation does not touch packages baked into container images or add-ons, so image rebuild pipelines, base-image refresh cadence, and SBOM-based verification need to be treated as separate controls from cluster/node upgrade channels.
- The Ubuntu `SecurityPatch` auto-upgrade channel is now the fastest path to kernel remediation for AKS Linux nodes; clusters on `NodeImage` or manual upgrade need an owned runbook or they will silently lag regional VHD availability.
- GitHub's `pull_request_target` default block is a CI/CD supply-chain control change with a hard deadline and brownout windows — organizations with fork-based PR automation must inventory workflows and encode explicit allow policies rather than relying on legacy permissiveness.
- Dependabot pausing on inactive repositories creates a governance blind spot for archived or dormant code that is still deployed; enforced security configurations are the durable way to keep alerting independent of repository activity.
- Preview capabilities in Copilot Studio (customer conversation harness, centralized Copilot Credit cost management) and GitHub secret scanning for Actions logs extend agentic and CI surfaces that will need identity, data-boundary, and cost-governance review before broad enablement.
- MDVM coverage expansion into Office Online Server, Skype for Business Server, Configuration Manager, MPEG-2 Video Extension, and Paint broadens vulnerability inventory scope; expect new findings against previously unreported software and align asset criticality rules accordingly.

## Security Operations Observations

- Two high-severity AKS CVEs land in the same window with different exposure paths (container image dependency vs. Linux kernel); detection engineering should confirm container image scanning and node-level vulnerability coverage both feed the same remediation queue with distinct ownership.
- The OpenSSL EOL bulletin will keep generating scanner noise on Azure Linux-based add-on images; SOC and vulnerability management should adopt distribution-aware matching and documented, time-bound exceptions to avoid repeated triage of EOL-only findings.
- GitHub secret scanning in Actions workflow logs is alert-list only during preview with no notifications and no backfill, so add a scheduled review of the secret scanning alert page to SOC or platform-team routines until notifications ship.
- New secret scanning detectors and false-positive suppression (SpaceX, Alibaba, AWS, Google, OpenVSX, Pydantic, Tencent) will change alert volume; retune suppression and escalation rules rather than treating the shift as incident signal.
- The `pull_request_target` brownouts on November 9 and 16 will produce failed workflow runs with error annotations — brief the SOC and release engineering so these are not escalated as pipeline compromise.
- MDE Linux and macOS November releases bundle a library upgrade and bug/performance fixes without named CVEs; track them through patch-compliance reporting rather than the incident workflow.
