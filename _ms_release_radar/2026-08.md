### Security Architect Observations

- **CVE data consumption change (Defender for Cloud):** The move of detailed CVE properties to the `microsoft.security/cvedetails` resource type is a breaking change for any automation, dashboards, or SIEM ingestion that reads CVE details from vulnerability assessment records. Architectures relying on ARG queries must be updated to avoid silent loss of CVE detail; plan for a migration window and validate query output.
- **Classic Defender for SQL API retirement:** With retirement on August 16, 2027, security architects should inventory all scripts, pipelines, and third-party integrations using the classic Vulnerability Assessment and Advanced Threat Protection APIs and plan migration to the supported configuration model well ahead of the deadline.
- **CIEM overprovisioned identity change (AWS/GCP):** Removing unused actions from overprovisioned identity assessments changes the meaning of these recommendations. Architectures that relied on Defender for Cloud CIEM for permission-usage validation must shift to native AWS IAM last-accessed and Google Cloud IAM insights, affecting multi-cloud governance workflows.
- **AKS security posture improvements:** Istio Gateway API disabling service account token auto-mount, Entra ID SSH rejection on AzureContainerLinux, and IMDS/outbound-type changes triggering reimages all improve default security posture but require Node Disruption Policy planning to avoid workload disruption during reimages.
- **npm supply-chain hardening:** npm v12 install-time security defaults (allowScripts off, git/remote dependency restrictions) and publish-time malware scanning change the software supply chain. Architects should update build pipelines to approve trusted scripts and tolerate publish-to-availability delays.
- **GitHub credential revocation granularity:** Token-type-specific revocation and deauthorization enables finer-grained incident response, but requires updating enterprise incident-response runbooks and REST API automation to leverage the new org-level and token-type capabilities.

### Security Operations Observations

- **Sentinel UEBA expansion:** New FortiGate behaviors and Check Point/Fortinet/Zscaler/GuardDuty anomaly rules add 10 new anomaly detections mapped to MITRE ATT&CK. SOC teams should review these rules for false-positive tuning, especially around VPN sign-in anomalies and high-risk web category access.
- **Defender for Storage targeted malware scanning:** On-demand malware scanning now supports scoping to specific blobs, files, containers, and file shares. SOC teams can reduce scan noise and cost by targeting high-risk items rather than entire storage accounts.
- **GitHub Actions malicious workflow holds:** Potentially malicious workflow runs are now held for approval on public repositories. SOC teams should establish a review process for held workflow approvals and monitor for abuse of the approval mechanism.
- **Dependabot malware alert expansion:** OpenSSF malicious-packages data now feeds Dependabot alerts across more ecosystems. Enable malware alerts if not already on, and expect an increase in alert volume requiring triage.
- **Dependabot version update cooldown:** A three-day default cooldown on version updates reduces supply-chain risk but may delay non-security updates; security updates still open immediately. SOC/DevSecOps should confirm cooldown settings align with their risk tolerance.
- **MDVM detection accuracy fixes:** Multiple MDVM detection fixes and new product support (Gimp CVEs, Orb, Cisco Webex, WSL Update, and 13 new products) reduce false positives and expand coverage; review affected vulnerability reports for accuracy improvements.
