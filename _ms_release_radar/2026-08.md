## ⛵ AKS

| Indicator | Feature | Type | Description |
|---|---|---|---|
| 🟢 | Node Auto Provisioning on restricted clusters | GA | Node Auto Provisioning can now be enabled on clusters with restricted `publicNetworkAccess`, including private API server VNet-integrated clusters using UDR, as long as AKS-wide networking guardrails pass. |
| 🟢 | Automatic availability zone placement | GA | Automatic availability zone placement is now enabled globally. Customers can create or update VMSS node pools with `availabilityZones=["auto"]`. |
| 🟢 | Control-plane only upgrades to LTS | GA | AKS now allows control-plane only upgrades to Long Term Support (LTS) as long as the version skew policy is satisfied, enabling safer validation before node pool upgrades. |
| 🟢 | AKS Node pool Rollback | GA | Node pool version rollback is now generally available, letting you restore a node pool to its previous Kubernetes version and node image after an upgrade issue. |
| 🟢 | Encryption in Transit for Azure Files CSI | GA | Encryption in Transit and workload identity to access Azure Files storage are now generally available for the Azure File CSI driver. |
| 🟡 | Prepared Image Specification (PIS) | Preview | PIS is now in public preview, allowing preconfigured node images with required container images and node customizations to reduce node startup times. |
| 🟡 | Capacity Reservation Group association | Preview | Customers using preview API version `2026-01-02-preview` or later can associate a Capacity Reservation Group with an existing node pool. |
| 🔵 | SSH node access triggers immediate reimage | New/Updated | For AKS clusters running Kubernetes 1.37 or later, SSH node access configuration changes now trigger an immediate node reimage; use Node Disruption Policy to control timing. |
| 🔵 | IMDS restriction and outbound type changes trigger reimage | New/Updated | For Kubernetes 1.37+, changes to IMDS restriction, network-isolated bootstrap profile, or cluster outbound type now trigger immediate node reimage. |
| 🔵 | VMSS rolling upgrade concurrency update | New/Updated | VMSS rolling upgrade concurrency for percentage-based maxSurge, maxUnavailable, and maxBlockedNodes is now calculated from current VMSS capacity and capped to remaining VMs. |
| 🔵 | Service principal to managed identity triggers reimage | New/Updated | Updating a cluster from service principal authentication to managed identity now triggers node reimages across node pools. |
| 🔵 | AKS upgrade validation for VMSS limits | New/Updated | Upgrade validation now rejects node pool upgrades where current pool size plus effective surge would exceed the VMSS 1,000-instance limit. |
| 🔵 | Istio Gateway API automountServiceAccountToken disabled | New/Updated | Istio Gateway API deployments now set `automountServiceAccountToken` to `false`, improving default security posture. |
| 🔵 | GPU MIG profile validation | New/Updated | AKS now validates GPU MIG instance profile slice width against VM SKU capacity. |
| 🔵 | Application Gateway for Containers ALB alignment | New/Updated | The Application Gateway for Containers ALB add-on is now aligned with AKS minor versions, with automatic selection of compatible controller images. |
| 🔵 | Entra ID SSH rejected on AzureContainerLinux | New/Updated | AKS now rejects Entra ID SSH configuration on AzureContainerLinux node pools due to incompatibility with immutable OS nodes. |
| 🔵 | Node Auto Provisioning Karpenter update | New/Updated | Node Auto Provisioning updated to Karpenter provider Azure v1.14.0, adding support for the `Balanced` consolidation policy. |
| 🔵 | Azure Policy add-on updates | New/Updated | Gatekeeper bumped to 3.23.0 and Azure Policy add-on bumped to 1.17.0. |
| 🔵 | CSI driver upgrades | New/Updated | Azure File CSI Driver upgraded to v1.34.7/v1.35.6; Azure Blob CSI Driver upgraded to v1.26.16/v1.27.9; Azure Disk CSI Driver upgraded to v1.33.11/v1.34.5. |

## Security Architect Observations

- **Multicloud security posture is expanding significantly** with over 200 new AWS and GCP recommendations now generally available in Defender for Cloud, directly affecting Secure Score. Security architects should evaluate coverage gaps across newly supported resource types and integrate these into continuous compliance programs.
- **Deprecation wave requires immediate migration planning**: Classic Defender for SQL APIs, Azure Operations Center, and legacy grouped recommendations are all being retired. Architecture teams must assess dependent automation, dashboards, and API integrations and build migration timelines.
- **AKS behavioral changes tighten the node lifecycle**: Immediate node reimages triggered by SSH, IMDS, network, and identity configuration changes on Kubernetes 1.37+ clusters increase operational risk. Architect Node Disruption Policy gates into maintenance windows and deployment pipelines to prevent unplanned workload disruption.
- **Supply chain security controls are tightening across GitHub and npm**: Install-time security defaults in npm v12, publish-time malware scanning, 2FA-bypass token restrictions, and GitHub Actions workflow approval controls all reduce attack surface but require CI/CD pipeline adjustments and developer communication.
- **Defender for Endpoint macOS release adds AI agent visibility**: The expanded local AI agent discovery including MCP server configurations on macOS reflects growing attack surface from AI tooling. Architect endpoint policies to discover and govern AI agent deployments.

## Security Operations Observations

- **Sentinel UEBA coverage grows for network and cloud telemetry**: New anomaly detection across Fortinet, Check Point, Zscaler, and AWS GuardDuty means SOC analysts will see additional behavioral alerts. Update detection rules, playbooks, and analyst training to incorporate firewall and cloud threat detections.
- **On-demand malware scanning in Defender Storage now supports scoped targets**: SOC and IR teams can request targeted scans of specific blobs or file shares rather than entire storage accounts, improving response precision and reducing scan time during investigations.
- **AKS node pool rollback is now GA**: Operations teams can restore node pools to previous versions after upgrade failures, reducing MTTR for cluster issues. Update runbooks to include rollback validation steps.
- **Credential revocation granularity improves in GitHub incident response**: Token-type-specific revocation allows more surgical containment during compromises. Update incident response playbooks to leverage per-credential-type kill switches.
- **Defender for Cloud CIEM removes unused action signals for AWS/GCP**: SOC and IAM teams relying on Defender for Cloud to identify unused permissions must now cross-reference native AWS IAM and GCP IAM tools, adding a step to overprovisioned identity workflows.
